# 事故と経緯の記録

CLAUDE.md から、規則そのものより**経緯の説明**が大半を占める節を移したもの（2026年9月30日）。
**削除ではなく移動**で、元の文章はそのまま残している。規則と数字の基準は CLAUDE.md の同名の節にある。
ここは「なぜその規則ができたか」を確かめるための記録で、規則を変えるときに読む。
規則を外す・緩めるときは、ここに書かれた事故が再発しないことを根拠にする（CLAUDE.md「ルールは仮説である」）。

## 存在しない CSS クラスは、ビルドも検査も通り抜ける

2026年9月3日、ガイドの「ツールの組み合わせ早見表」を `.table-scroll` という
**CSS に存在しないクラス**で包んでいた。正しくは `.article-table-scroll` か
`.vibe-tool-table-wrap` で、**単語ひとつ違っていた。**

`overflow-x: auto` が当たらないまま `min-width: 36rem` の表が置かれた結果、
**ページ全体が横に 435px はみ出し、モバイルでは画面が縮小表示になっていた。**
崩れたのは表だけではなく、その節の本文すべてである。

| | |
|---|---|
| ビルド | 通る |
| React | 何も言わない |
| `review-check.mjs` | 記事データを見るので掛からない |
| 発見者 | **読者の目視** |

`check-css-classes.mjs` が `checks.yml` で検査する。スタイルを持たないクラスは
正常でありうるため、`scripts/allowed-classless.txt` に**理由を添えて**登録する。
まとめて登録しないこと。**登録の前に、似た名前の既存クラスがないか必ず確認する。**

**横あふれは計測できる。** 疑わしいときは、同一オリジンの iframe に幅 390px で
読み込み、`documentElement.scrollWidth - clientWidth` を見る。修正前 435px、
修正後 8px と数字で確認できた。スクリーンショットの目視より確実である。

なお残る 8px は `.storage-notice` の全幅表示（`100vw - 100%` の負マージン）に
よるもので、**スクロールバーが常時表示される環境でのみ生じる。**
iOS の重ね表示スクロールバーでは `100vw === 100%` になり 0 になるため、
**計測環境だけの見かけであり、直してはならない。**

## 記事だけが白紙になるのは、デプロイとキャッシュの噛み合わせである

2026年9月4日の朝、更新直後に「記事が Safari で見れない」という報告があった。
トップもガイドも表示されるのに、**記事ページだけが完全な白紙**だった。

原因はブラウザではない。**遅延読み込みのチャンクとハッシュの噛み合わせ**である。

| index.html が最初に読むもの | 記事を開いた時に読むもの |
|---|---|
| `index-*.js` / `data-articles-meta-*.js` | **`ArticleDetail-*.js` / `data-articles-body-*.js`** |

チャンク名にはハッシュが付き、**デプロイのたびに変わって古いファイルは消える**
（GitHub Pages はサイト全体を置き換える）。ブラウザに古い `index.html` が
残っていると、消えたハッシュを取りに行って 404 になる。

**壊れ方が部分的なので、原因が見えにくい。** 最初に読み込まれるものだけで
描けるトップとガイドは表示され、別チャンクを要する記事だけが落ちる。
iOS Safari で顕在化しやすいのは HTML のキャッシュが強いためで、
**Safari の不具合ではない。**

エラー境界が無かったため React がツリーごと落とし、`<div id="root"></div>` だけが
残っていた。**読者からは真っ白なページに見え、何が起きたのか分からない。**

**直し方は2段構え。** `retryChunk`（`src/utils/lazyChunk.js`）が、取得に失敗したら
使い捨てクエリ `_r` を付けて **新しい `index.html` を取り直す**。
ただの `location.reload()` では同じキャッシュを引きうるため、別 URL にして
確実に取得させる。無限ループを避けるため、やり直しは**セッション中1回だけ**。
それでも駄目なら `ChunkErrorBoundary` がメッセージを出す。

**境界は `Suspense` ごとに置く。** アプリ全体を1つの境界で包むと、チャンク1つの
失敗でヘッダやナビまで消える。失敗した部分だけが差し替わる形にする。

**この種の欠陥は、消えたチャンクを再現すれば確かめられる。** 該当チャンクだけ
404 を返すサーバを立ててビルド成果物を配れば、修正前は
`<div id="root"></div>`、修正後は記事本文が出ることを数字で確認できる。

## 「新着が見える場所」は掲載日で並べる

記事には日付が2つある。**`date`（掲載日 = サイトに載せた日）**と
**`newsDate`（出来事の日 = 事実が表に出た日）**で、2026年9月4日時点で387件中278件がずれていた。
レビュー記事では最大433日離れる（モデルの発表日と執筆日の差）。

2026年9月4日、朝に5本公開したのに**トップは前日のままだった**。
並び順が `newsDate` だったためである。

| 記事 | 掲載 | 出来事 | 並びでの位置 |
|---|---|---|---|
| NVIDIA が Hugging Face を買収 | 9/4 | 9/2 | 一覧8位 |
| Anthropic × Salesforce | 9/4 | **8/26** | **一覧17位＝2ページ目** |

**公開初日から2ページ目にある記事は、無いのと同じである。**
RSS も `pubDate` が出来事の日だったため、購読者のリーダーで新着が下に沈んでいた。

**「サイトに何が増えたか」を見せる場所は、すべて掲載日で並べる。**

| 場所 | 並び | 実装 |
|---|---|---|
| トップのヒーロー・最近のニュース | 掲載日 | `HomePage.jsx` |
| 「本日のニュース（東京日付）」 | 掲載日 | `App.jsx`（出来事の日で「今日」を探すと前日の記事が居座る） |
| 記事一覧の日付順 | 掲載日 | `compareArticleOrder` |
| RSS の `pubDate` / 並び | 掲載日 | `generate-feed.mjs` |
| sitemap の `lastmod` | 掲載日 | `generate-sitemap.mjs` |

同じ日に複数公開したときは、**出来事の新しいほうを先に見せる**。

**どちらの日付も隠さない。** カードは掲載日を主に出し、出来事の日がずれている
場合だけ「（出来事 YYYY-MM-DD）」を併記する。一覧の説明文も「掲載日の新しい順」に
揃える。**説明文と実際の並びが食い違ったままにしない。**

`newsDate` を掲載日に書き換えて解決してはならない。**出来事がいつ起きたかを
偽ることになる。** 直すのは並び順であって、データではない。

## 用語集の点検は、ガイド本文の言及とは別物である

週次の計器（`weekly-metrics.mjs`）にも似た節があるが、あちらは
**「ガイド本文のどこかに文字列が出るか」**を見ている。この2つは大きく違う。

| 2回以上使われたタグ 221件 | |
|---|---|
| ガイド本文のどこかに出る | 129 |
| **用語集に見出しがある** | **35** |

**94件が「触れられてはいるが、定義は無い」**状態だった。ツール別ページの
一文に出てくることと、用語集を引いて説明があることは別である。読者が
「エッジAI とは」と思って用語集を開いたときに何も無ければ、どこかの本文に
一度出ていたかどうかは関係がない。

**タグは用語集の語彙の代理にならない。** 機械的に候補を出すと134件になり、
大半が分野の分類（「セキュリティ」「規制」）、記事の型（「速報」「比較」）、
固有名詞（「Alphabet」「WWDC」「iOS」）だった。
「初出が最近の語だけ」に絞る案も試したが、Android・EU・Sol・DeepMind が
並んで改善しなかった。

そこで**一度だけ人手で分類し、`scripts/allowed-non-glossary.txt` に記録した**。
以後は未分類の新しいタグだけが候補に出る。134件 → 21件になり、
マルチエージェント・エッジAI・オープンウェイト・Computer Use・
コンテキストウィンドウなど、**すべてが本物の候補**になった。

**この一括登録は例外である。** `allowed-classless.txt` で「まとめて登録しない」
と定めているのは、そこでの1件1件がクラス名の取り違えを示唆するからである。
こちらは既存の分類済みバックログの記録であり、性質が違う。
**新しいタグを足すときは1件ずつ理由を添えること。**

## 企業台帳は、記事の期限切れ検査では拾えない

`aiCompanies.js` の全社が時間で腐るデータ（従業員数・売上・評価額・株式）
を持つのに、**更新の経路も鮮度の検査も長く無かった。**

実例。台帳は Hugging Face を「未上場・評価額 $4.5B（2023年）」としていたが、
同じ日にサイトが出した記事は **NVIDIA による $12.93B での買収**を報じていた。

記事用の `check-expired-content.mjs` は**料金・提供条件を示す語が近くにある
期限**だけを拾う設計である。台帳で問題になるのは料金ではなく**事業イベント**
（買収のクローズ、施設の稼働開始）なので、同じ検査では拾えない。
`check-company-data.mjs` を別に立てている。

**鳴りすぎる検査は無視される。** 最初の実装では2つの誤検出を出した。

- 「同じ文字列に将来語があれば全部の日付が約束」→ 過去の出来事まで拾った。
  **日付の直後に将来語が来る場合だけ**に限定した
- 「年の記載が無い社は古い」→ 57/71社が並んだ。Adobe や Apple のように
  年を書く性質でない社が多い。**年が入っている社だけ**を対象にした
